**Change**: The user separately downloaded two files that were never
integrated: `funky-amen_175bpm.wav` (175 BPM, ~11s) and
`funky-drummer-drums_105bpm_E_minor.wav` (105 BPM, ~4.6s) — still sitting
in the user's Downloads folder, not copied into the repo. The two loops
actually shipped this session (`amen_174bpm_1bar.wav`,
`funky_drummer_174bpm_1bar.wav`) needed no tempo work because they were
already pre-cut to exactly one bar at 174 BPM. These two are not — using
them means real tempo-matching, not just `toMonoResampled`'s length-only
resampling.

**Do not**: reuse `toMonoResampled()` as-is for this. It only interpolates
sample count to hit a target length — for a big tempo ratio like
105→174 BPM (~1.657×), that resampling changes pitch too (old-school
"vinyl varispeed" style, pitch and time shifting together, ~+8.4
semitones). That might be a legitimate stylistic choice (classic jungle
producers did exactly this), but it is a real aesthetic call to make
deliberately, not something to ship as an unexamined side effect of reusing
existing code.

**Done when**: either (a) real pitch-preserving or varispeed-style
tempo-matching is implemented and these two loops are wired in as
additional options, with a decision recorded on which pitch behavior was
chosen and why, or (b) the decision is explicitly "not worth it, the
pre-cut loops already cover this need" — recorded in `docs/STATUS.md`
either way, not left silently unaddressed.

**Verify**: if implemented, a new test analogous to
`src/test/break-loop.test.ts` covering the tempo-matched output length
and pitch expectation. If declined, no code change — just the doc entry.
